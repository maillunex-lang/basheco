# BASHECO: единая бесшовная карта населённого пункта

Утверждённая структура: Республика → муниципалитет → населённый пункт → единая карта. Городские районы Уфы являются зонами одной карты, а не отдельными игровыми мирами. Соседние кварталы не требуют экранов загрузки.

## Техническая модель

Один населённый пункт имеет стабильный location_id и общую систему координат. Чанки по 64×64 клетки используются только для подгрузки и рендера. Ключ чанка: (location_id, chunk_x, chunk_y). Координаты участков и зданий остаются глобальными в рамках населённого пункта; ID объектов не меняются при переходе через границы чанков. Точное соответствие клетки метрам и картографическая проекция будут определены после проверки исходных геоданных.

## Что уже внедрено

Клиентский помощник city_chunks.gd вычисляет номера чанков и видимые чанки; world.gd применяет общую проверку пересечения участков с видимой областью. Smoke-тесты проверяют границу 63/64 и пересечение четырёх чанков. Отрисовка по-прежнему ограничена видимыми клетками.

## Что ещё НЕ сделано

Сервер пока возвращает все участки прототипа Уфы. Нет серверного API чанков, клиентского кэша и выгрузки, реального рельефа, полной геометрии Уфы, синхронизации обновлений по чанкам и нескольких игровых карт поселений. Размер 200×200 остаётся размером начального прототипа, а не пределом города.

## Следующие шаги

1. Ввести серверный каталог локаций и привязать прототип Уфы без потери данных.
2. Добавить серверную выдачу участков по координатным чанкам с тестами и защитой от дубликатов.
3. Реализовать в Android асинхронную подгрузку ближайших чанков, кэш, удаление далёких объектов и обновление после строительства.
4. Импортировать и корректно спроецировать OSM/DEM для дорог, зданий, лесов, воды и высот, сохраняя лицензионную атрибуцию.
5. Проверить память и FPS на реальных Android-смартфонах.

Пока эти этапы не пройдены, нельзя считать карту полноценной бесшовной копией Уфы.
