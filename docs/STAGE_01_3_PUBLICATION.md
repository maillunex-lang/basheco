# Этап 1.3.4: подготовка публикации пилотной локации

Дата: 12.11.2026. Изменения в GitHub; **в рабочей БД и работающих контейнерах не применялись**.

## Реализовано

- `generated_storage.publish_location(settlement_id)`: явная серверная операция публикации, только для утверждённой Михайловки `S80652440101`.
- До публикации выполняются проверки занятости сгенерированных клеток в `world_plots` (прямоугольники по глобальным координатам) и `world_object_cells` (постройки игроков).
- Конфликт блокирует операцию; данные игрока не перемещаются и не удаляются.
- Повторный вызов для уже опубликованной локации возвращает `unchanged=true`.
- Добавлен тест запрета публикации посторонних населённых пунктов.

## Проверки

- `PYTHONPATH=server python3 -m unittest discover -s server/tests -p test_generated_storage.py -v`: 6 тестов успешно.
- `server/sql/016_generated_locations.sql`: применена в **отдельном временном контейнере PostgreSQL 18**, обе таблицы созданы. Контейнер удалён.
- Реальный импорт и публикация в БД пока **не выполнялись**. Проверки SQL на столкновения с реальными данными и одновременное строительство не проведены.

## Блокирующие вопросы

1. **Гонка операций:** блокировка публикации через advisory lock защищает от одновременного импорта, но создание игроком участка или объекта пока не использует эту блокировку и не проверяет клетки опубликованной генерации. Перед живой публикацией нужно добавить симметричные транзакционные проверки в пути строительства, включая legacy-пути.
2. **Интеграционный тест:** отдельная PostgreSQL БД с полными таблицами `world_plots` и `world_object_cells`, реальные тесты отказа при конфликте, повторного импорта и rollback.
3. **Публикация через администрирование:** пока это внутренняя функция, не открытый API для администратора. Нельзя давать игрокам доступ к публикации.
4. **Godot:** подключение авторизованного чтения опубликованных чанков и списка доступных пунктов; тест на Android.

Поэтому этап 1.3.4 пока **не закрыт**, а новая миграция не применена к рабочему серверу.
