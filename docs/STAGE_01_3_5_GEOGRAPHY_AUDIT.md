# Этап 1.3.5: географический аудит кандидатов

Дата: 12.11.2026. Только исходники в GitHub, без применения к рабочей БД и без изменения запущенных контейнеров.

## Проверено

Команда: `PYTHONPATH=server python3 -m basheco.geography_audit --output build/geography_audit.json`.

Аудит проверяет 5 контрольных точек каждого объекта (четыре угла и центр) на принадлежность муниципалитету с помощью уже сохранённых OSM-границ (EPSG:32640, слой детализации с допуском упрощения 40 м). Генерация, каталог населённых пунктов и публикация не изменяются. Результат является отдельным отчётом и воспроизводится без сети и БД.

Результат на текущем наборе: 252 кандидата, 252 без обнаруженных нарушений по выборочным точкам, 0 обнаруженных конфликтов. Михайловка также прошла эту **предварительную** проверку.

## Что НЕ доказано

- Упрощённые административные границы не являются точной кадастровой границей. Проверка пяти точек не исключает пересечения ребром границы.
- Нет проверенных геоданных о водных объектах, заболоченности, уклоне, рельефе, охраняемых территориях и правах на землю.
- Координата населённого пункта не является разрешением строить в этой точке.
- **Все 252 кандидата имеют `safe_to_publish=false`.** Никакой объект не получает автоматического разрешения на публикацию.

## Дальнейший безопасный шаг

Согласовать официальные источники водных объектов и рельефа, реализовать полноценную проверку пересечений геометрий без допущений, затем добавить серверный блокирующий допуск перед публикацией. До этого пилот остаётся только подготовленным, но не подтверждённым как географически безопасный.

Тесты: `PYTHONPATH=server python3 -m unittest discover -s server/tests -p test_geography_audit.py -v`. Не путать предварительный аудит с готовой системой безопасности.
