# Этап 1.3.2: ограниченный генератор кандидатов

В тестовой версии **не более пяти населённых пунктов на муниципальный район или городской округ**. Полный официальный реестр не сокращается.

## Правила отбора

1. Учитываются только пункты с подтверждёнными координатами внутри муниципалитета и положительным **подтверждённым населением с источником**. Ранжирование по численности населения, убывание; при равенстве по стабильному ID. Источники и годы населения могут отличаться; это не единый свежий рейтинг переписи.
2. В каждом муниципалитете максимум 5 кандидатов. Уже утверждённая пилотная Михайловка включена в квоту Уфимского района, даже если она не в топ-5.
3. По текущему реестру получается **252 кандидата из 63 муниципалитетов**, но в клиентском списке **по-прежнему опубликована только Михайловка**. Остальные кандидаты скрыты до проверки и публикации построек.
4. Не создавать «недостающие» пункты для достижения пяти. Отсутствующее население не приравнивать к нулю или выдуманному значению.

## Генерация

`PYTHONPATH=server python3 -m basheco.location_generator` создаёт локальный `build/location_candidates.json` (не входит в релиз и не публикуется автоматически). На каждый выбранный пункт: стабильный seed SHA256 от ID и версии генератора, 6-метровая глобальная сетка, чанки 64×64, 61 клетка дорог и 15 схематичных домов с различными размерами. Пересечения запрещены. Объекты пока **кандидаты**, не игровые активы и не записи БД. При повторном запуске с тем же справочником результат побайтно воспроизводим.

## Проверка

В изолированной копии запускались четыре теста из `server/tests/test_location_generator.py` напрямую через Python, все прошли. `pytest` на VPS не установлен, поэтому нельзя заявлять о его запуске. Ранее опубликованный APK, API и БД не изменены.

## Оставшиеся задачи до «полноценного» серверного генератора

- Перенести объекты в серверное хранилище с версиями и уникальными ID; безопасно мигрировать данные и не перезаписывать изменения игроков.
- Проверять пересечения с существующими участками и административными границами, ограничения рельефа и водоёмов.
- Реализовать публикацию после проверки, отдачу чанков через API и динамическое обновление клиентского списка.
- Проверить нагрузку и APK с несколькими опубликованными локациями.
- Уточнить население по единому официальному периоду, если появится полный достоверный набор данных.

Пока это **проверенный генератор кандидатов**, а не законченная MMO-система строительства.
