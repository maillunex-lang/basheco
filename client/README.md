# BASHECO Godot client

Godot 4 project (checked with Godot 4.6-stable). Import once with
`godot --headless --path client --import`, run with `godot --path client`.

## One world

There is a single scene and a single coordinate system for the whole republic:
EPSG:32640 metres, 6 m cells, 64×64-cell chunks, one origin (`scripts/world_grid.gd`,
identical to `server/basheco/world_grid.py`). A settlement is a region of that world.
Choosing one in the geography menu moves the camera; no other map is loaded.

- `scripts/world.gd` — camera, input, plots. Global cells are integers; drawing is
  relative to `render_origin`, a chunk-aligned cell that follows the camera.
- `scripts/geo_background.gd` — atlas `data/world/`, chunk streaming (on-screen chunks
  plus one ring, at most 64, two loads per frame, far chunks are freed).
- `scripts/geo_chunk_node.gd` — one chunk drawn once in cell space; panning only
  moves node transforms. Level of detail depends on zoom.
- `data/world/` is generated by `python -m basheco.world_atlas` from
  `server/geodata/`. Do not edit it by hand: a server test rebuilds and compares it.

The map shows real OpenStreetMap geometry (© OpenStreetMap contributors, ODbL 1.0)
and SRTM contours. Coverage is partial: a small extract of central Ufa and the
village of Mikhailovka. Empty ground means "not imported yet". OSM buildings are
background only and never become playable plots.

Controls: drag with one finger or middle mouse button, pinch or mouse wheel to zoom,
tap or left click to select a plot. Zoom range 0.004–2.4.

## Administrative navigation (stage 1.2)

The municipal selector uses the complete, versioned OKTMO registry, not the two
settlements in the imported OSM atlas. Open the geography menu, choose a district
or urban okrug, then a settlement. The search field finds settlements across the
republic and within the selected municipality; namesakes are distinguished by
type, unit, municipality and OKTMO code. Lists are paged for Android.

- `data/admin_navigation.json` is generated from `server/geodata/admin/`:
  **63 municipalities, 4,561 settlements**, with 4,538 confirmed destinations.
- To regenerate at repository root: `python3 tools/export_navigation.py`.
  The GitHub Action `navigation-catalog.yml` also updates this tracked file.
- 23 destinations with missing or inconsistent coordinates remain in the catalog,
  but cannot move the camera to an unverified position.
- Most settlements do **not** yet have detailed OSM imagery. Navigation to them
  works on the common grid; the generator of playable locations is a later stage.
- Detailed verification and Android acceptance criteria:
  `docs/STAGE_01_2_NAVIGATION.md`.

## Server

Plots come from `GET /v1/world/viewport` in global world cells. The client refuses
plots if the server's grid version differs from its own. The token stays in memory;
non-local connections require HTTPS. Legacy settlement-local `tile_x/tile_y` are
never used to place anything.

## Tests

```sh
python3 -m unittest discover -s server/tests -p test_navigation_catalog.py -v # official data checks
godot --headless --path client -s tests/grid_parity.gd      # client math == server pyproj
godot --headless --path client -s tests/smoke.gd            # world, streaming, travel, UI
godot --headless --path client -s tests/navigation.gd       # all settlements, search, camera, invalid coordinates
godot --headless --path client -s tests/streaming_soak.gd   # memory and chunk release
python server/tests/e2e_world_client.py                     # real API + this client
```

Android: `godot --headless --path client --export-debug Android out.apk` (needs export
templates, Android SDK build-tools and a debug keystore). A debug-signed APK must not
be published as a release.

## Android debug alpha (invite-only)

The Android client is the only active platform for the alpha. Godot 4.6 is
required to reproduce the build. Workflow
[`Android alpha APK`](https://github.com/maillunex-lang/basheco/actions/workflows/android-alpha.yml)
checks the Godot UI, navigation, and map, signs a debug build, and uploads a
`BASHECO-Android-alpha-debug` artifact for 14 days. Signatures are temporary
CI debug keys, **not** release credentials. A phone with an APK signed by a
different key may need that existing installation removed; safeguard local data
first. Use Android ARM64 hardware in landscape mode. The demo geography works
without a game server; player login and persistent MMO gameplay require a
separately tested HTTPS backend. Passing headless smoke tests does not replace
real-device acceptance testing.

### Alpha parcel creation (requires updated test server)

After login, select a supported test settlement (Ufa or Mikhailovka) and
open **Стройка**. Choose the settlement and a zoning type; center the map on
the intended **game-only** location and press **Создать тестовый участок у центра карты**.
The client obtains authoritative legacy anchors from `/v1/world/grid`,
converts the camera cell to the alpha plot API's legacy indices and sends
`POST /v1/world/plots`. The server checks the quota (at most three per
account and settlement), parcel conflicts and generated occupancy; a rejection
never results in a locally invented parcel. On success the client centers the
map on the returned global cells. Select that plot on the map to construct a
zone-compatible prototype building via the server-validated endpoint. These
plots are not cadastral ownership or real construction permissions.
